# WB5E ST77916 显示恢复与帧率验证

日期：2026-11-08。开发板 WB5E / BK7258，屏幕 W180TE010I / ST77916，360×360、RGB565、QSPI0 四数据线 80 MHz。

## 已完成的结果

- 已通过 COM11 烧录 `H:\BK7258\firmware\all-app_recovery-r1.bin`，烧录器最终返回 `Download complete, all pass`。
- 用户在实屏确认：**颜色正常，闪烁已消失，动画正常**。
- 启用 0→160→0 km/h 的连续扫表动画，每个方向 5 秒，0.1 km/h 精度。
- 两段串口采样共 26 个统计窗口，实际完成发送为 **72.1–79.0 fps**，窗口均值约 **75.7 fps**；渲染与发送计数一致。
- 每帧 DMA 完成等待的窗口均值约 **10.64 ms**，观察到的最大等待为 **12 ms**。
- 保留超过 60 fps 的配置，未锁帧为精确 60.000 fps。这里的帧率是应用渲染和 QSPI 发送完成率，并非对面板内部扫描率的测量。
- 两段采样覆盖约 50 秒，含多个完整往返扫表周期；采样未见 Assert、HardFault 或 DMA 超时。未进行长时间老化测试。

## 本次修正

1. 删除整帧就地反显、字节交换，以及回调中再次变换的实验代码。原路径会让用于下一帧的底图混入另一种像素格式，且回调未调用 SDK 的帧缓冲归还函数。
2. LVGL 始终在原生 RGB565 数据上渲染和混合。旋转后，仅对新绘制的独立小块做 `bswap16(~pixel)`，随后复制到 SDK 管理的显示缓冲。显示缓冲从始至终保持面板传输格式，不修改已提交的帧，不修改 LVGL 可复用的原始绘制缓冲。
3. 保留 SDK 的双帧缓冲领取、复制和归还流程，不创建独立转换帧缓冲，不用时间戳猜测 DMA 是否空闲。
4. QSPI 的 BY_FRAME 分支在 DMA 完成后立即回调归还缓冲，避免直到下一条请求才归还末帧；增加传输完成计数及等待耗时统计。BY_LINE 分支保持原路径。
5. 暂停未应答触摸的 LVGL 轮询，避免 I2C 读取在显示线程中最多阻塞 50 ms。此前只有约 15 fps；本次联合修正后达到约 75 fps，尚未做独立变量实验量化每项改动的收益。

仍采用厂家初始化表、`0x3C` 写显存命令、80 MHz、320 MHz CPU、双帧缓冲、LVGL 任务间隔 2 ms、LVGL 刷新周期 10 ms、`UI_MODE=1` 的局部失效优化。没有恢复早期已被否定的“循环移位 5 位”补偿，也没有开启 DCache。

## 代码与复现

主工程：`H:\BK7258\code\projects\wb5e_lvgl`。

SDK 补丁统一保存在 `H:\BK7258\code\patches`：

- `lv_port_disp_v9.c`：小块颜色转换、SDK 帧缓冲管理和渲染计数。
- `bk_display_qspi_ctlr.c`：BY_FRAME 完成归还和发送统计。
- `lcd_qspi_st77916.c`：实际使用的厂家表、0x3C、80 MHz。
- `lv_conf_v9.h`：本次实际使用的 LVGL 配置。

本次已同步 Windows SDK 与 WSL `/root/bk7258` 的对应文件，并将原来未同步的 UI_MODE、CPU 主频、双缓冲、任务间隔配置同步回 code 主工程。构建脚本现在先同步主工程和以上补丁，再构建；只覆盖内容发生变化的目标文件。原始备份在本目录的 `backup-*` 和 `source-sync-backup` 子目录。

```powershell
# 编译并导出为 firmware\all-app_wb5e_lvgl.bin
wsl -d Ubuntu-22.04 bash /mnt/h/BK7258/code/scripts/build.sh wb5e_lvgl

# 恢复本次已获实屏确认的固件
& H:\BK7258\code\scripts\flash.ps1 -Bin H:\BK7258\firmware\all-app_recovery-r1.bin -Port COM11

# 采集实际发送帧率；采集期间串口应空闲
python H:\BK7258\code\scripts\capture_display.py --seconds 30 --output H:\BK7258\code\logs\display-check.txt
```

`fix_display_20261108.py` 是已执行过的一次性修复脚本，不应重复执行；日常编译使用 `build.sh`。
