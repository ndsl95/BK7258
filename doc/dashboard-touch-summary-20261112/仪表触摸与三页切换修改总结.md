# WB5E 仪表触摸修复与三页切换修改总结

日期：2026-11-12。工程：`code/projects/wb5e_lvgl`。硬件：WB5E / BK7258、W180TE010I 圆屏，ST77916 QSPI 显示、360 × 360，CST816D 触摸。

这轮工作先恢复触摸，再加入左右滑动切页，最后将滑动门槛从 **65 像素降到 40 像素**，并把第三页的蓝牙设置预览放进固件。触摸修复版和两页滑动版通过实屏验证；这轮的三页展示版编译通过，未由本任务烧录。

## 触摸修复

旧代码解除 P20/P21 的 GPIO 复用后，当前 SDK 配置下调用 `bk_i2c_init()` 不会自动恢复引脚复用。显式配置硬件 I²C0 后，首次上板仍然没有应答，但手指操作触发了 159 个 P5 中断，说明问题集中在通信链路。实机进一步确认，现有屏幕线序与 SDK 硬件 I²C0 的固定线序相反。

| 信号 | 台架现有接线 | SDK 硬件 I²C0 接线 |
| --- | --- | --- |
| SCL | P21 | P20 |
| SDA | P20 | P21 |
| 触摸复位（低有效） | P4 | P4 |
| 触摸中断 | P5 | P5 |

固件先试硬件 I²C0，未识别到芯片时再用开漏方式尝试台架原接线，所以现有屏幕无需改线。台架从 7 位地址 `0x15` 读到芯片 ID `0xB6`。I²C 读写放在独立任务，GPIO 中断只发信号，LVGL 从队列取坐标和按下、松开事件，避免通信超时阻塞显示任务。

修复版的实屏点按和滑动得到 **252 帧有效触摸数据、0 次读取错误**。另以串口确认两页仍能切换，随机扫表短测显示发送约 **68–72 fps**。

## 滑动切页与屏幕旋转

画面使用 `ROTATE_90`，手势按旋转后的画面方向判断。把屏幕上的数字看正，手指从右往左移动是左滑，从左往右移动是右滑。松手时检查净位移，横向位移必须达到门槛，且至少是纵向位移的 1.5 倍。点按、纵滑和因通信异常取消的触摸不会切页。

两页版以 **65 像素**为门槛：仪表首页左滑进入保护板页，保护板页右滑返回首页。实屏复测记录 **15 次手势切页**，包含 7 次完整往返和最后一次进入保护板页；读取错误为 0。首页右滑和保护板页左滑不会切换，这是两页版的边界行为。

## 三页展示版

将门槛从 **65 像素降到 40 像素**，约为圆屏直径的九分之一。页面顺序为 **仪表首页 → 保护板数据 → 蓝牙设置**：左滑前进一页，右滑返回一页，首尾不循环。

蓝牙设置页沿用原来的圆屏预览，标明「未连接 / 展示模式」，搜索按钮禁用。这个固件仅展示界面，不扫描、不连接，也不写入绑定记录。页面资源编译为 360 × 360 的 LVGL I4 图像；打包后解码像素与预览图逐像素一致。

三页展示版单独输出固件，未覆盖默认固件文件。编译成功，AP Flash 占用 **96.17%**。当时另一任务在使用烧录设备，本任务没有打开串口或烧录；此固件的三页手势与实屏显示仍待验证。
